START HERE / 研究摘要

这个库，如何帮助我们积累研究？

数据库保存记忆，模型理解与分析，
我们的应用负责采集、更新和核验。

01 能力
整理资料与经历，检索相关记忆，生成带来源的分析，并维护可更新的经验归纳和专题知识。
02 实现原理
模型抽取信息后写入以 PostgreSQL 为主的存储；组合语义、关键词、图关系和时间检索，再由模型综合证据。Bank 是逻辑记忆范围，不是每个项目独建一套数据库。
03 使用场景
持续研究与技术选型、开发排障、长期客户服务，以及需要跨会话理解历史和复用经验的 Agent。
04 对我们的意义
把已有 GitHub 研究、源码发现、实测结果和选型理由作为来源，持续做跨项目比较、回查依据、修正过期结论，减少重复调研。

输入是资料、经历及其来源；输出是相关记忆、分析回答、专题知识和 Agent 上下文。采集与同步需要接入，分析结论需要核查；目前完成的是研究整理与网页展示，个人知识库方案尚未实施。

03 / WHEN IT FITS

什么时候值得增加一层记忆？

对象长期存在，信息持续变化，
而且过去的结果会影响下一次行动。

A

个人研究助手

跨项目找回已有发现、实测结果和否决理由，减少重复调研。

值得保存来源 · 版本 · 结论 · 验证状态
B

研发与排障助手

把架构决策、故障条件与处理结果，带入后续开发任务。

值得保存环境 · 动作 · 结果 · 失败原因
C

长期客户服务

让多轮服务理解过去的问题、承诺与处理进展，减少背景重复。

值得保存诉求 · 约束 · 承诺 · 状态变化
D

重复执行任务的 Agent

在相似条件下检索过去经验，作为本次行动的参考，而不是自动照搬。

值得保存适用条件 · 反馈 · 成功与失败
先用简单方法的情况

一次性文档总结、稳定手册查询、固定步骤的短流程。历史经验很少被复用时，额外的抽取、归纳与维护成本可能不值得。

采用之前，核对三个边界

有记忆，不等于有可靠判断。

01中文需要整条检索链配合

除了中文 LLM，还要检查多语言嵌入、重排与中文分词。官方文档所列默认本地模型和原生全文配置偏向英文。多语言配置 ↗

02源信息、抽取与归纳都可能出错

保留来源、区分事实与推测，审查纠正后的结论。检索到真实存在的记忆，并不证明记忆内容真实或推理正确。记忆库分组也不能替代应用的访问鉴权。权限扩展 ↗

03效果要和成本一起测量

记录写入成本、背景归纳开销、回答耗时与失败情况。作者论文报告 LongMemEval 最高 91.4%，属于特定实验设置，不能直接当成你的中文任务准确率。论文 ↗ · 性能说明 ↗

04 / DIRECTIONS TO BUILD

在记忆之上，还能构建什么？

以下为研究建议，尚未实现或验证。

优先 01

研究证据管理

区分官方声明、源码发现、本人实测与待验证推测，为每条结论补上版本和出处。

可核对
优先 02

任务经验与操作手册

把条件、动作、结果和失败原因连起来，再将验证过的经验整理为可复用步骤。

可复用
优先 03

个人、项目与团队记忆

定义共享范围与访问权限，通过应用编排决定查哪些记忆库；跨库汇总需要自行设计。

可协作
贯穿全程

记忆质量与生命周期

用纠错、过期、删除和证据引用用例，检查认识是否更新、旧结论是否继续误导回答。

可评估

可利用的接口：租户与身份扩展、操作校验、HTTP 接口和 MCP 工具扩展。具体业务规则仍需实现。查看扩展点 ↗

FIRST EXPERIMENT建议方案 · 尚未执行

从一组真实记录开始

  1. 01
    选择 3–5 个研究项目

    整理约 30–50 条材料，保留日期、来源与验证状态。

  2. 02
    设计约 20 个检验问题

    加入明确纠错、条件变化和找不到依据的情况。

  3. 03
    比较三种方式

    直接搜索文档、基础 RAG、Hindsight，使用同一组材料。

答案正确性引用支持度新旧状态耗时与成本

采用标准：它是否减少了重新解释背景、重复调研和重复踩坑的次数。材料还少时，先积累高质量记录；材料很多却难以复用时，再评估记忆层的收益。
